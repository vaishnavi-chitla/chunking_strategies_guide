Chunking Strategies for RAG Applications

Chunking is simply the act of splitting larger documents into smaller units (“chunks”). Each chunk can be individually indexed, embedded, and retrieved.

Because RAG pipelines often rely on retrieval from vector databases and large language models (LLMs) with limited context windows, smart chunking can make all the difference in delivering relevant, context-rich answers.

Why Chunking Matters

  • Context Window Constraints: Well-sized chunks ensure limits are not exceeded.
  • Improved Retrieval Efficiency: Smaller chunks improve recall and speed.
  • Computational Optimization: Reduces unnecessary processing.
  • Enhanced Relevance: Preserves semantic meaning for better answers.

Role of Chunking in the RAG Pipeline

Document Ingestion → Preprocessing → Chunking → Embedding → Vector Storage → Retrieval → Generation

Chunking acts as the critical bridge between raw documents and meaningful vector representations.

Overview of Chunking Strategies

1. Fixed-Size Chunking

Definition

This is the simplest approach, segmenting text into equally sized pieces (using character, token, or word counts). Often, an overlap is introduced to maintain continuity of ideas.

Example Usage

from langchain_text_splitters import CharacterTextSplitter

document = """
LangChain is a framework for developing applications powered by language models.
It enables chaining LLMs with external tools.
Chunking is a critical step in RAG systems.
"""

text_splitter = CharacterTextSplitter(
    chunk_size=15,
    chunk_overlap=0,
    separator=""
)

texts = text_splitter.split_text(document)

for i, chunk in enumerate(texts):
    print(f"Chunk {i+1}: '{chunk}'")

Library Used

LangChain – CharacterTextSplitter

Example Output

Chunk 1: 'LangChain is a'
Chunk 2: ' framework for '
Chunk 3: 'developing appl'
...

Drawbacks

  • May cut off sentences or paragraphs abruptly.
  • Ignores natural semantic breaks.
  • Relevant information can end up scattered across chunks.

2. Semantic Chunking

Definition

Instead of arbitrarily slicing text by length, semantic chunking splits documents at logical boundaries (e.g., sentences, paragraphs, or sections). Often, consecutive segments that are highly similar may be merged, providing coherent text blocks.

Example Usage

from langchain_experimental.text_splitter import SemanticChunker
from langchain_community.embeddings import HuggingFaceEmbeddings
from langchain_core.documents import Document
from dotenv import load_dotenv

load_dotenv()

doc_text = """
LangChain is a framework for developing applications powered by language models.
It enables chaining LLMs with external tools.
Chunking is a critical step in RAG systems.
"""

documents = [Document(page_content=doc_text)]

embeddings_model = HuggingFaceEmbeddings(
    model_name="sentence-transformers/all-MiniLM-L6-v2"
)

semantic_chunker = SemanticChunker(
    embeddings_model,
    breakpoint_threshold_type="percentile",
    breakpoint_threshold_amount=90
)

semantic_docs = semantic_chunker.create_documents(
    [doc.page_content for doc in documents]
)

print(f"Total semantic chunks: {len(semantic_docs)}")

for i, doc in enumerate(semantic_docs):
    print(f"--- Chunk {i+1} ---")
    print(doc.page_content)

Library Used

LangChain Experimental + HuggingFace Embeddings

Total semantic chunks: 2

Chunk 1:
LangChain is a framework for developing applications powered by language models.
It enables chaining LLMs with external tools.

Chunk 2:

Drawbacks

  • More complex to implement.
  • Yields variable chunk sizes.
  • Slightly higher computational requirements.

3. Recursive Chunking

Definition

Recursive chunking relies on a hierarchy of separators. The algorithm attempts to split on high-level separators first, then moves to increasingly finer separators if chunks remain too large.

Example Usage

from langchain_text_splitters import RecursiveCharacterTextSplitter

text_splitter = RecursiveCharacterTextSplitter(
    chunk_size=35,
    chunk_overlap=0
)

document = """
LangChain is a framework for developing applications powered by language models.
It enables chaining LLMs with external tools.
Chunking is a critical step in RAG systems.
"""

chunks = text_splitter.split_text(document)

for i, chunk in enumerate(chunks):
    print(f"Chunk {i+1}: {chunk}")

4. Document-Based Chunking

Definition

In this chunking method, we split a document based on its inherent structure. This approach considers the flow and structure of content but may not be as effective for documents lacking clear structure.

Document with Markdown: Langchain provides MarkdownTextSplitter class to split document that consist markdown as way of separator.

Document with Python/JS: Langchain provides PythonCodeTextSplitter to split the python program based on class, function etc. 

from langchain_text_splitters import PythonCodeTextSplitter

python_code = """
import math

class Calculator:
    def add(self, a, b):
        return a + b

    def sqrt(self, x):
        return math.sqrt(x)

def divide(x, y):
    if y == 0:
        raise ValueError("Cannot divide by zero")
    return x / y
"""

splitter = PythonCodeTextSplitter(
    chunk_size=200,
    chunk_overlap=0
)

chunks = splitter.split_text(python_code)

for i, chunk in enumerate(chunks):
    print(f"--- Chunk {i+1} ---")
    print(chunk)

Document with tables: When dealing with tables, splitting based on levels 1 and 2 might lose the tabular relationship between rows and columns. To preserve this relationship, format the table content in a way that the language model can understand (e.g., using <table> tags in HTML, CSV format separated by ';', etc.). During semantic search, matching on embeddings directly from the table can be challenging. Developers often summarize the table after extraction, generate an embedding of that summary, and use it for matching.

Example Usage

import pdfplumber 

import pandas as pd 

  

def extract_tables_pdfplumber(pdf_path): 

    all_tables = [] 

    with pdfplumber.open(pdf_path) as pdf:

                df = pd.DataFrame(table[1:], columns=table[0]) if table and len(table) > 1 else pd.DataFrame(table) 

                all_tables.append(df) 

    return all_tables

5. Agentic Chunking

Definition

Traditional chunking strategies (fixed-size, token-based, sentence-based) assume that clean, linear text is already available. In practice, many real-world documents contain scanned pages, images, tables, and complex layouts that cannot be reliably processed using standard Python-based text extraction libraries. These approaches operate purely on extracted text length rather than on visual or semantic understanding, often resulting in missing content, fragmented ideas, or poorly structured input for downstream RAG systems.

By leveraging Vision Language Models, documents can be interpreted in the same way a human reads them by jointly understanding visual structure, text, images, and tables. This produces a faithful, semantically rich textual representation of the document. Agentic chunking then builds on this high-quality extraction by delegating chunking decisions to an LLM, enabling reasoning over meaning and document structure rather than relying on rigid, syntactic boundaries.
